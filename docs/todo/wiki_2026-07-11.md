### Alerts, activity & agenda

### Supplier lookup / scraping (companion browser extension)

## 3. Page conventions (house style)

Every page follows the same shape so the wiki reads as one document:

- **Title (H1)** matching the sidebar entry, then a one-sentence summary of what the feature
  is and why you'd use it.
- **"Where to find it"** line (nav path / screen) near the top.
- **Screenshots:** auto-generated, cropped to the relevant UI, referenced as
  `![alt](images/<page>-<n>.png)`. Every screenshot has descriptive alt text.
- **Box-outs** (issue requirement) using GitHub blockquote callouts, used where they genuinely
  help — not decoration:
  - `> **💡 Tip** …` — a shortcut or better way.
  - `> **ℹ️ Note** …` — clarification / how it interacts with another feature.
  - `> **⚠️ Heads-up** …` — a gotcha or destructive-action warning.
- **Cross-links** to related pages with `[[Page-Name]]` wiki links.
- **Inside a table cell, escape the wiki-link separator:** `[[Label\|Page-Name]]`. GitHub renders
  the wiki with GFM, which splits table rows on unescaped `|` *before* resolving `[[…]]`, so an
  unescaped separator tears the link in half — the row gains a phantom column and the link renders
  as literal text. In prose the separator must stay **unescaped**, or the backslash shows up.
  `src/lib/wiki-table-links.test.ts` enforces both directions.
- **Modular-UI note** where a page documents an optional feature: a short line that it can be
  hidden/shown on the [[Modular-UI]] screen.
- Plain, neutral, user-facing language — no internal/process/plumbing detail (public repo).

## 4. Screenshots — automated capture

A dedicated `scripts/wiki-screenshots.mjs` (modelled on `scripts/browser-smoke.mjs`: Playwright
driving Edge against `vite preview` with a real cross-origin-isolated OPFS context):

1. **Seed synthetic data** through the app's own flows (or a seed import) — invented items
   (e.g. "M3×10 socket screws", "Raspberry Pi 5"), locations ("Garage", "Workshop shelf"),
   a contact ("Alex Rivera"), a supplier — **all fake**, `example.com` only, no real people.
2. Navigate to each documented surface, open the relevant dialog/panel, and capture a
   **cropped** screenshot (element bounding-box clip) into `docs/wiki/images/`.
3. Deterministic viewport + theme (default accent, light) for visual consistency; a dark
   variant only where a page is specifically about theming.
4. Named `<page-slug>-<n>.png` to match the page references.

Screenshots are regenerated by re-running the script, so they stay current as the UI evolves.

## 7. Publishing to the wiki repo

Publishing is **automatic**. `docs/wiki/` is the single source of truth; the
`BootBlock/Gubbins.wiki` repo is a mirror of it, and nothing else writes there.

`.github/workflows/publish-wiki.yml` syncs the two whenever a change to `docs/wiki/` lands on
`main`, so a merged wiki edit is live without anyone remembering a chore. It can also be run by
hand from the Actions tab to force a re-sync.

This was manual for a long time, and that is precisely why the published wiki drifted — link
fixes and a whole page sat unpublished while the source was correct. Automating it removes the
step that kept being forgotten.

**What the workflow does:**

1. Runs `scripts/wiki-check.mjs` (locally: `npm run wiki:check`) and stops if it fails — every
   `[[link]]` must point at a page that exists, every referenced image must be present, and no
   image may be orphaned. The same check runs in the Tests workflow, so a broken link fails the
   PR that introduced it rather than the publish that would have shipped it.
2. Clears the wiki checkout (keeping `.git`) and copies `docs/wiki/` over it. Clear-then-copy
   makes this a **mirror**: a page deleted from `docs/wiki/` is deleted from the wiki, rather
   than lingering there forever as an append-only copy would leave it.
3. Commits and pushes, naming the source commit. If nothing changed it is a clean no-op.

It authenticates with the job's built-in `GITHUB_TOKEN` (`contents: write`) — no personal
access token is stored, which keeps a long-lived credential out of a public repo's secrets.

**Notes:**

- The wiki repo's default branch is `master`, not `main`.
- Editing a page directly on GitHub works, but the next publish **overwrites it**. Make the
  change in `docs/wiki/` instead.
- Escaping of the `|` separator in table cells is guarded separately, by
  `src/lib/wiki-table-links.test.ts` in the unit suite.
- After a change that alters a table or adds a page, it is still worth glancing at the
  **rendered** page under `https://github.com/BootBlock/Gubbins/wiki/` — reading the markdown
  is what let the table-link bug ship in the first place, and rendered output is the only thing
  that settles it.
