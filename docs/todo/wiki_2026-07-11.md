## 1. Feature audit (against the code, 2026-07-11)

Sourced from the SSOTs — `feature-registry.ts` (every toggleable page + capability),
`nav-destinations.ts` (top-level routes), `SettingsDialog.tsx` (every setting), the
`docs/todo/*` shipped backlogs, and the README Features section. Grouped as the wiki will be.

### Inventory (core)
- Items: categories, custom fields, weighted **capabilities**, quantities, photos,
  attachments (files or URLs), notes, **condition grading** (Mint / Good / Needs Repair /
  Out for Calibration), acquired date, archive/restore.
- **Tracking modes:** discrete ("Bulk"), serialised (per-unit), untracked, consumable gauge.
- **Locations:** hierarchical, colour-coded, descriptions, per-location item counts,
  capacity/fullness gauge.
- **Per-location stock ledger:** quantities tracked independently per location + transfers.
- **Batches / lots:** beneath each location, expiry dates, FEFO consumption.
- **Variants & SKUs** (parent/child) and **Kits & bundles** (live "how many can I build?").
- **Tags & attachments;** **related items** ("works with" / accessory / spare-for).
- Low-stock thresholds + at-a-glance gauges; per-item **activity log**.
- **Bulk edit / clone;** inventory **views** (visual / list / table density, group-by,
  favourite filter, card customisation).

### Asset lifecycle
- **Warranty** tracking + derived status; straight-line **depreciation** + replacement value.
- **Current value + revaluation log** (manual, appreciating assets).
- **Maintenance & servicing** schedules (time- and usage-based; usage accrues checkout-hours;
  per-location scheduling).
- **Per-instance test / calibration / service records** (serialised units).
- **Cycle counting** + reconciliation (discrete/serialised/per-location/per-batch) + guided
  **audit day** walk.
- **Insurance / estate schedule** (room-by-room replacement values, print → PDF).

### People, loans & bookings
- **Contacts** (people + suppliers). **Loans:** check out/in to a contact, overdue tracking,
  returns to original location + lot, full audit trail. **Bookings:** reserve over a date
  range with overlap detection.

### Search
- FTS5 full-text (prefix, stemming, fuzzy). **Visual query builder.** **Text syntax**
  (`field:value`, `cap:key>n`, `AND`/`OR`/parentheses). **Natural-language** box.
  **Capability** search + best-match ranking. **Saved searches** + favourites filter.

### Scanning & labels
- Camera scanning (native BarcodeDetector + `@zxing` WASM fallback + main-thread fallback);
  adaptive frame-skip, selectable symbology. **Continuous scan** + batch actions
  (move-all, check-out-all). Per-item deep-link QR + printable A4 label sheets.
- **OCR** receipt/label prefill (on-device Tesseract WASM, opt-in, reviewable).

### Purchasing & projects
- **Projects** with BOM, component reservations, budgets, project export sub-folders.
- **Purchase orders** (in-transit qty, partial/split receipts). **Reorder / shopping list.**
  **Wishlist** (wanted-but-not-owned). Supplier parts + price breaks + **price history**.

### Reports & insights
- Valuation by category/location, stock-movement trends, dead-stock, ABC, turnover, aging,
  valuation-over-time. **Spend** + **sales & margin** analytics. **Data-hygiene** checks.
  CSV export. Printable **parts catalogue** + **insurance schedule**.

### Sales & disposals
- Record items sold / written off → feeds sales & margin report.

### Alerts, activity & agenda
- **Activity** ledger (every change). **Alerts** feed (low stock, expiries, overdue loans,
  due maintenance/warranty). **Upcoming** agenda (booking returns, loan due-backs, servicing,
  warranty expiries). Optional **OS reminder notifications** (installed PWA, local-only).

### Supplier lookup / scraping (companion browser extension)
- Scrape datasheets/parameters; parsers for DigiKey, Mouser, Farnell, LCSC, RS, Adafruit,
  SparkFun, Amazon + generic fallback. Barcode → product lookup. One-click price refresh.

### Data, sync & resilience
- Local-first, fully offline; in-browser SQLite (WASM + OPFS) = SSOT.
- Cloud sync: File System Access folder **or** Google Drive (backend-less OAuth) — LWW.
- Backup & restore: portable `.zip` → Merge or Replace (guarded destructive path).
- Export/import: Markdown vault or raw `.sqlite`; bulk import (CSV/TSV/JSON/MD/free-form);
  one-click **migration** from another tool. **Storage triage** dashboard.

### Integrations — Bridge / Home Assistant (second audience)
- Opt-in local bridge (off by default; `GUBBINS_BRIDGE_*` flags). HTTP + **MCP** query API.
- **Home Assistant** custom integration (mDNS discovery, voice "where are my…", entities);
  optional write-back. **Webhooks + SSE**, **MQTT** discovery, **iCal** feeds, feeds/metrics.
- SSOT for the security posture: `bridge/README.md` permission & security matrix.

### Interface, settings & accessibility
- **Modular UI:** hide pages + capabilities per-device; first-run preset chooser; Modules
  screen. **Dashboard:** drag-and-drop widget board. **Appearance:** mode (light/dark/system)
  × accent colour, OLED, high-contrast, visual effects / "reduce effects". **Language &
  region** (English + German today, per-key English fallback). **Notifications.** **Kiosk /
  tablet mode** + wake-lock. **Command palette.** Installable PWA + offline indicator.
  Accessibility throughout (focus trap, ARIA tree, skip links, live regions, reduced motion).

## 3. Page conventions (house style)

Every page follows the same shape so the wiki reads as one document:

- **Title (H1)** matching the sidebar entry, then a one-sentence summary of what the feature
  is and why you'd use it.
- **"Where to find it"** line (nav path / screen) near the top.
- **Screenshots:** auto-generated, cropped to the relevant UI, referenced as
  `![alt](images/<page>-<n>.png)`. Every screenshot has descriptive alt text.
- **Box-outs** (issue requirement) using GitHub blockquote callouts, used where they genuinely
  help — not decoration:
  - `> **💡 Tip** …` — a shortcut or better way.
  - `> **ℹ️ Note** …` — clarification / how it interacts with another feature.
  - `> **⚠️ Heads-up** …` — a gotcha or destructive-action warning.
- **Cross-links** to related pages with `[[Page-Name]]` wiki links.
- **Modular-UI note** where a page documents an optional feature: a short line that it can be
  hidden/shown on the [[Modular-UI]] screen.
- Plain, neutral, user-facing language — no internal/process/plumbing detail (public repo).

## 4. Screenshots — automated capture

A dedicated `scripts/wiki-screenshots.mjs` (modelled on `scripts/browser-smoke.mjs`: Playwright
driving Edge against `vite preview` with a real cross-origin-isolated OPFS context):

1. **Seed synthetic data** through the app's own flows (or a seed import) — invented items
   (e.g. "M3×10 socket screws", "Raspberry Pi 5"), locations ("Garage", "Workshop shelf"),
   a contact ("Alex Rivera"), a supplier — **all fake**, `example.com` only, no real people.
2. Navigate to each documented surface, open the relevant dialog/panel, and capture a
   **cropped** screenshot (element bounding-box clip) into `docs/wiki/images/`.
3. Deterministic viewport + theme (default accent, light) for visual consistency; a dark
   variant only where a page is specifically about theming.
4. Named `<page-slug>-<n>.png` to match the page references.

Screenshots are regenerated by re-running the script, so they stay current as the UI evolves.

## 6. CLAUDE.md upkeep rule (this issue)

Add a mandatory convention: when a change adds or alters a user-facing feature/setting/concept,
the corresponding wiki page(s) under `docs/wiki/` **must** be updated (or a new page added to
the taxonomy in this file) in the same change — the same discipline as design tokens and i18n.
Feature work is not complete until the wiki reflects it.
